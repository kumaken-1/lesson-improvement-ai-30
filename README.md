# 生成AI 30のチャレンジⅣ ～授業改善を生成AIとの対話で進める～

**公開ページ: https://kumaken-1.github.io/lesson-improvement-ai-30/**

課題づくり、発問、子どもの見取り、交流、評価、授業後の見直しを題材に、明日の授業で変える一点を見つける30回です。実際に同僚から出た授業の悩み（発言が同じ子に偏る、話し合いが深まらない、評価規準と活動がずれる、など）をもとに構成しています。気になる回を、ひとつ試すところから始められます。

**この講座の目的は、完成した指導案を作ることではありません。10分で成果物を仕上げるのではなく、教師の判断を一つ前へ進めることを1回の単位にしています。**

## 参加のしかた

- 自由参加です。30回すべてをやる必要はありません。
- 順番も速さも自由です。1日に何回やっても、間があいてもかまいません。
- ランキング、提出、成績評価はありません。取り組んだ数を競う企画でもありません。
- 授業前の準備で完結する回（課題づくり、発問の検討、見取りの準備など）と、授業をしたあとに使う回（見取り、評価、授業後の見直し）の両方があります。
- 生成AIを開けないときは、文章を読んで「どんな回答が来そうか」を考えるだけでも参加できます。

## 1つの回の進み方

回をひらくと、次の順で並んでいます。**手順の番号は1回目から2回目まで通しで振ってあります。**

1. **1回目に送る** — 生成AIに送る文章と、そこまでの手順
2. **回答が来ます** — 何を見ればよいかを1行で書いています。ここがその回のねらいです
3. **2回目に送る** — 空欄を自分の言葉でうめて、新しいメッセージとして送ります

添付や貼り付けが必要な回は、**添付と文章が同じメッセージで、送信は1回**であることを手順に明記しています。

**10回講座（Ⅰ）と校務版（Ⅱ）と同じ進み方です。** シリーズを通して操作の型を変えていません。参加するたびにやり方を覚え直さずにすむようにするためです。

### 1回目の文に空欄がある回があります

30回のうち15回は、1回目に送る文そのものに空欄があります。「私は『____』だと考えています」のような形で、そこに自分の見立てを書いてから送ります。

**記入欄を別に立てていません。** 自分の見立てを書く行為と、送る文を組み立てる行為が同じ1つの操作になります。AIの出力を先に読んでから考えるのではなく、自分の考えを先に置いてAIに当てる形です。

### AIの回答を短くしています

**AIに送る文には、全30回とも次の制約が付いています。**

> Web検索はせず、ここに書いた情報だけを使ってください。各項目は2文以内で書いてください。

教材や授業案を渡す回には、さらに「貼った内容にない一般論は足さないでください」（資料を添付する回は「資料にない一般論は足さないでください」）が付きます。

この制約がないと、AIは学習指導要領や外部サイトを検索して長い回答を返します。長く整った回答と、検索してきた権威ある記述は、教師の判断を弱めます。この講座で必要なのは詳しい授業助言ではなく、短時間で吟味できる分量の回答です。

制約は回ごとの本文ではなく `js/view-model.js` の `PROMPT_LIMITS` にあります。30回すべてに同じ文が付くため、回ごとに書き分けません。

### 使わないという判断も結論です

回答を読んだら、採用するか、直すか、使わないかを決めます。**使わないという判断も、その回の結論です。**

この判断は画面のボタンではなく、文で伝えています。選択肢を押させる仕組みにすると、Ⅰ・Ⅱと操作の型が変わってしまうためです。

AIを使わないほうが、子どもが迷い、言葉を探し、教材や友達と直接向き合える場面があります。

### 最後に変える一点を書き留めます

各回の終わりに、次の授業で変える一点を一行だけ書き留めます。授業案ではなく、発問、順番、時間の使い方、見取る場面のような、実行できる形にします。

**書く場所はこの画面ではなく、手元の手帳や指導案です。** 画面に記入欄を置いていないのは、授業記録や子どもの発言に触れた言葉を端末に残さないためです。

## 大切にしていること

生成AIの回答は「正解」や「完成品」ではなく、考えるための材料です。採用するか、直すか、使わないかを決めるのは教師です。

**AIに任せないことを、はっきり決めてあります。**

- 子どもの実態や内面を、限られた情報から決めつけること
- 授業のねらい、子どもに何を残すか、どの発言を取り上げるかの最終判断
- AIが作った授業案を、実際の子どもや教材に照らさずそのまま実施すること
- AIの整った表現を、子どもの完成形や正解として与えること

### 学習指導要領や理論をAIに尋ねる回はありません

**AIは平然と、存在しない記述を作ります。** そのため30回とも、AIに外部の知識を尋ねません。

AIに渡すのは、自分が持っている材料だけです。教材、自分の授業案、自分の授業記録、自分の考えの4つです。AIに求めるのは、視点を出すこと、反対意見を言うこと、見落としを指摘すること、整理することです。事実は元の資料や原典で確かめてください。

## 扱う授業改善の場面

| 場面 | 回数 | 例 |
|---|---|---|
| 課題づくり | 5 | 自分で取り組む課題を検討する、選ばせることと考えさせることのずれを見る、ノートの記述から次の指導を見つける |
| 問いをつくる | 5 | めあてと発問の重なりを見分ける、発問の誘導に気づく、正解が早く出たあとの問い返しを作る |
| 子どもの現在地 | 5 | 聞き役になる子の事実と推測を分ける、発言しない子の考えを発言以外で確かめる、個々の違いを学級全体の問いに変える |
| 活動と対話 | 5 | 発言が偏る事実を整理する、ペアと全体の間の壁を探る、ICTで対話が増減する子への配慮を考える |
| 見取りと評価 | 5 | 活動の中で見取れることを絞る、評価規準と活動のずれを見つける、テストの点と理解のずれを確かめる |
| 授業後の見直し | 5 | うまくいかなかった原因を場面まで絞る、想定外の発言をねらいに結びつける、予定と違ったところに学びの芽を探す |

教科を限定しない回が中心です。道徳・算数など、教科固有の場面を扱う回もいくつか混ぜてあります。

## 散りばめてある対話の型

30回のケースには、生成AIとのやり取りをうまくするための型がいくつも仕込んであります。読み進めるうちに自然と身につきますが、先に知っておきたい人のために挙げておきます。

- **先に自分の考えを書く** — AIの答えを読む前に、空欄に自分の見立てを書きます。AIの言葉に引っ張られないためです。
- **「〜しないでください」で縛る** — 一般論やお世辞に流れないよう、してほしくないことを先に伝えます。
- **あまのじゃくにさせる** — 子どものふりをして、わざと期待と違う答えを返させます。自分の発問の誘導に気づく方法です。
- **反対の立場から見せる** — 同じ出来事を、逆の見方でも説明させます。どちらか一方に決めつけないためです。
- **番号で指して続ける** — 返ってきた答えの「1つ目」「2つ目」を指して、同じ会話のまま深掘りします。
- **名前を伏せてから渡す** — 子どもの記録を扱うときは、渡す前に名前を置き換えます。

## 操作の種類と色

「そのままコピーすればよいのか、自分で何か足すのか」が分かるように、操作の種類ごとに色とラベルを分けています。

| 色 | ラベル | 利用者がすること | 回数 |
|---|---|---|---|
| 黄 | 空欄をうめてから送る | 文の空欄に、自分の考えを書いてから送る | 15 |
| 緑 | 自分の文を貼ってから送る | 教材や授業案を貼り付けてから送る | 11 |
| 紫 | 資料を添付してから送る | 資料を添付してから送る | 4 |
| 赤 | 注意 | この色は注意以外で使いません | |

**そのままコピーして送るだけの回はありません。** 自分の教材や授業案が入らない回は、教科も教材も子どもの現在地も設定されない一般論になるためです。

色は2番目の手がかりです。**ラベルとアイコンだけで何をするか決まる**ようにしてあるので、色の見分けが難しい人でも困りません。

## くわしく

実際に詰まる4か所にだけ、補足を用意しています。回ごとに書き分けず、共通の4本を参照しています。

- 添付ボタンの場所
- 1回で送る
- 新しいメッセージ
- 貼り付け

補足は**押しても、マウスを乗せても開きます**。マウスのない携帯やタブレットでも読めるようにするためです。

## 印刷して使う

[`print.html`](./print.html) が印刷用の一覧です。**A4縦2列で全15ページ**、1ページに2回分が載ります。校務版（Ⅱ）と同じ紙面です。

1回分が2ページに分かれることはありません。必要な回だけ刷りたいときは、ページ番号を指定してください。

紙面には、画面と同じ順で全部載っています。**記入欄は置いていません。** 書き留めるのは手元の手帳や指導案です。

## 記録

「やってみた」の印だけを、利用中の端末に保存します。件数や達成率、ごほうびの仕組みはありません。

## プライバシーとデータ

- 児童・保護者・職員の氏名、顔、連絡先、学習の記録、健康に関する情報などの個人情報や、学校の機密情報を入力・撮影・添付しないでください。
- 資料を渡す回では、**個人が分かる情報を取り除く手順を、資料を渡す前の手順として示しています。** 子どもの名前は「児童A」などに置き換えます。
- 練習には、同梱の練習用素材を使ってください。
- 入力欄は、送る文の空欄だけです（2回目は全30回、1回目は空欄をうめて送る15回）。書いた言葉はこのサイトの外へ送らず、端末にも保存しません。画面を閉じると消えます。
- 「やってみた」の印だけを `localStorage` に保存します。入力内容や生成AIの回答は収集しません。
- 外部API、アクセス解析、広告、トラッカーは使用しません。生成AIサービスとの通信もこのサイトからは行いません。

授業記録や子どもの振り返りは、校内の資料の中でも個人情報が残りやすいものです。この講座がそれらを扱うため、**入力欄の内容を一切保存せず、書き留める場所も画面の外に置いています。**

### 練習用の素材

資料を貼ったり添付したりする回では、探す手間で止まらないよう練習用の素材を同梱しています。すべて架空の内容で、実在の学校・自治体・団体・人物とは関係ありません。子どもの名前にあたる部分は「児童A」などの役割名に置き換えてあります。**サイトのトップページからも開けます。**

- `assets/sample-text.md`：架空の物語文教材（書き下ろし。人物が判断を変える場面をはっきり書いていない形）
- `assets/sample-reflection.md`：架空の振り返りの記述10人分（薄い記述、的が外れた記述、白紙を混ぜてあります）
- `assets/sample-board-plan.md`：架空の板書計画（子どもの言葉を教師のきれいな表現に直した形）
- `assets/sample-worksheet.md`：架空のワークシート（模範解答を先に見せている形）
- `assets/sample-lesson-record.md`：架空の授業記録（教師が流した発言を含む形）

**この5件には、教室で失敗しやすい形をわざと入れてあります。** 良い例ではありません。直すところを探す練習に使ってください。

## 使い方

### GitHub Pages

公開後はURLをブラウザで開くだけで使えます。携帯にも対応しています。

### ローカルで見る

このリポジトリを取得し、プロジェクト直下で静的ファイルを配信します。

```powershell
python -m http.server 4173
```

その後、`http://localhost:4173/` をブラウザで開きます。ビルドツールやAPIキーは不要です。

## 開発・確認

Node.js 22以降を想定しています。

```powershell
npm test
npm run build:print
npm run test:smoke
```

- `npm test`: 内容、記録、画面構造、印刷用ページ、公開文書のテスト
- `npm run build:print`: `js/challenges.js` から印刷用の `print.html` を再生成
- `npm run test:smoke`: ブラウザで主要操作を確認

## 内容を更新する

本文の正本は [`js/challenges.js`](./js/challenges.js) です。更新後は `npm run build:print` を実行し、画面と印刷用ページの内容をそろえてから `npm test` を実行してください。生成済みの `print.html` を直接編集しないでください。

1回分は7つの項目を持ちます。`id` `category` `title` `intro` `send` `reply` `followUp` です。10回講座・校務版と同じ構造で、`send` に4種類目の送り方 `fill`（空欄をうめてから送る）が加わっただけです。`fill` の回は `send.hint` に空欄へ入れる語の例を持ちます。

改善提案や誤りの報告は、公開リポジトリのIssueまたはPull Requestで歓迎します。実在する児童・保護者・職員や学校内部の情報は、Issue、Pull Request、サンプルデータ、画像のいずれにも含めないでください。
